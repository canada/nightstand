# Nightstand

iPhone の StandBy 風に、アナログ時計・カレンダー（日本の祝日対応）・天気を表示する静的ページ。ビルドや追加ライブラリは不要。

- 公開ページ: https://canada.github.io/nightstand/
- iPhone: Safari で開く → 共有 → ホーム画面に追加（Web アプリとして開く）
- 祝日: 内閣府 `syukujitsu.csv`（取得できない場合は holidays-jp API）
- 天気: 国内は気象庁の予報・アメダスを優先し、時間別予報や不足項目・海外はOpen-Meteoで補完（位置情報、または `?lat=35.68&lon=139.76` で固定）
- 操作: 右上を1回タップでボタン表示 → もう1回タップでモード切替（自動 / ナイト / デイ）。上下スワイプ・ホイールで月移動（クラシックは左右スワイプ）

## 開く

- [標準版](https://canada.github.io/nightstand/)
- [クラシック](https://canada.github.io/nightstand/classic.html)
- [確認用サイト](https://nightstand-preview.canadie.chatgpt.site/)（本人のみアクセス可能）

通常のURLで月移動・週間表示・天気詳細・タイマー・Google連携を備えたリッチ版を開く。固定位置は `?lat=35.68&lon=139.76`。以前の `?next=1` は不要で、付けても同じ標準版になる。クラシックは `classic.html` で独立して開く。GitHub Pagesは `main` ブランチのルートを配信する。

- カレンダー上の上下スワイプ、縦ドラッグ、マウスホイール、上下キーで前月・翌月へ移動する。年月と曜日の見出しは同じ位置に固定し、日付が指について縦に動く。月の切り替え時は年月が移動方向に合わせて縦に回転する（動きを減らす設定では回転しない）。今月では見出しに今日の日付と曜日も表示し、別の月ではその月の祝日名を下部に表示する。短いドラッグは元の月に戻る。前月末・翌月初めの日付は控えめな色で並べ、月をまたぐ週を途切れさせない。年月横の戻る矢印で当月に戻る。左右キーも利用できる。
- カレンダーの日付は大きめに表示し、日曜・祝日は淡い赤、土曜は淡い青で区別する。ナイトモードでは赤系の配色を保つ。
- カレンダーの週の行を押すと、その週の7日分を時間軸付きの週間表示で開く。前週・次週・今週へ移動でき、祝日は終日欄と下部に表示する。「Googleカレンダー」から接続すると共有・追加済みのカレンダーを選択し、予定を読み取り専用で重ねて表示する。Googleの祝日カレンダーにも対応し、日本の祝日は接続なしでも表示する。接続設定は[Googleカレンダー連携](docs/google-calendar.md)を参照。
- 普段の天気表示はアイコン・気温・天気の説明・最高／最低気温を表示し、押すと現在の詳細、今後12時間、7日間の予報を表示。詳細は開いたときに取得し、15分間キャッシュする。取得できない場合は前回の予報であることを表示し、再取得できる。
- 時計を押すとタイマーを表示。1・3・5分のプリセット、任意の分・秒の設定（初期値10分）、停止・再開・キャンセルに対応。開始するとすぐ時計へ戻る。時計内には残り時間だけを小さく表示する。元の設定時間はタイマーの操作画面で確認できる。計測中の表示を押すと操作画面を開き、終了後の `00:00` は押すと消える。押さなくても10秒後に自動解除する。
- タイマーは端末内に保存し、再読み込み後も締切から残り時間を復元する。「音を試す」で出力を確認でき、再生できなかった場合は操作画面に案内を表示する。通知音の再生時には一時停止した音声機能の再開を試みる。通知音はページが動作中の場合に鳴る。端末のロックやブラウザ停止中の音・通知は保証しない。復帰すると経過時間を反映する。

## 天気の出典

日本国内では[気象庁の天気予報](https://www.jma.go.jp/bosai/forecast/)の地域・週間予報と[アメダス観測](https://www.jma.go.jp/bosai/amedas/)を優先する。位置情報を気象庁の予報区ポリゴンと照合し、その地域の予報・気温の予報地点・観測地点を選ぶ。広域の週間予報は気象庁の地域対応表を使用し、近くても別の地域の観測値を使わない。

- 天気の説明・週間予報・最高／最低気温・降水確率は気象庁を優先する。気象庁にない気温の欄などはOpen-Meteoで補完する。今日・明日の降水確率は、発表後の6時間区分の最大値を表示する。
- 現在の気温・湿度・風速・1時間降水量は、同じ予報区の近いアメダスの正常な観測値を優先する。現在の気温は観測地点の値で、今日の天気の説明は予報として区別する。
- 1時間ごとの予報・体感温度・日の出／日の入り、取得できなかった項目と気象庁の対象地域外は[Open-Meteo](https://open-meteo.com/)を使用する。取得元を画面に示し、気象庁の情報を取得できなかった場合も明示する。
- 空欄を0に変換せず、今日の最高気温の繰り返し欄を最低気温として使わない。別の提供元の最高／最低を合わせて矛盾する場合は補完値を欠測にする。
- 予報と観測は15分、地域・観測点の公開メタデータは7日間キャッシュする。発表・観測時刻を表示し、取得失敗時の前回データは古い情報として明示する。観測が1時間以上前の場合は現在値へ使わない。

気象庁ホームページの公開JSONを直接取得する。固定された正式APIの仕様とは限らないため、データの欠損や形式変更は補完元への切り替えで扱う。出典と加工して表示している旨を画面に記載する。天気コードの説明・アイコン区分は気象庁の天気予報ページのTELOPSをもとに表示用に加工している。[気象庁の利用条件](https://www.jma.go.jp/jma/kishou/info/coment.html)、[府県天気予報の解説](https://www.jma.go.jp/jma/kishou/know/kurashi/yoho.html)。

クラシック版は従来のOpen-Meteoによる表示を維持する。標準版ではその取得だけを止め、気象庁の表示を古い取得処理が上書きしないようにする。

## コードの分離

`index.html` は既存のマークアップとリッチ版の入口を持つ。`classic.html` は追加機能を読み込まない独立した入口として元の画面を維持する。`classic.css` と `classic.js` は元のスタイルと処理をそのまま切り出したもの。`classic.js` の小さな `NightstandClassic` インターフェースを通じて、月移動・天気のアイコンや表示・位置情報取得を再利用する。

`enhancements.js` は機能の読み込みと初期化を行う。機能間の接続はこの入口で行い、追加機能のJavaScriptとCSSには同じ版番号を付ける。
週間表示は基本機能の初期化後に読み込む。Google連携も週間表示の後に独立して読み込む。週間表示の読み込みが遅れたり失敗したりしても、月移動・タイマー・天気詳細は利用できる。

| ファイル | 役割 |
| --- | --- |
| `month-calendar.js` | 月表示、日付・祝日の表示、クラシックの更新を受ける処理 |
| `calendar-gestures.js` | 月移動のスワイプ・ドラッグ・ホイール・キー操作 |
| `week-calendar.js` / `.css` | 週の選択と週間表示 |
| `calendar-dates.js` | 月表示と週間表示で共用する日付の計算・表記 |
| `sheets.js` | ダイアログの開閉、キーボード操作、タッチ操作の共通処理 |
| `forecast.js` | 気象庁優先の天気統合、補完、キャッシュ、通信失敗と再取得 |
| `jma-weather.js` | 気象庁の予報区選択、府県・週間予報とアメダス観測の取得・正規化 |
| `weather-detail.js` / `.css` | 天気詳細の描画 |
| `timer.js` / `.css` | タイマーの状態・保存・描画 |
| `google-calendar.js` | Google公式認証ライブラリの読み込み、タブ内の認証・カレンダー一覧・選択した予定の週単位の取得 |
| `calendar-events.js` | 予定の日別分割と重複時間の配置計算 |
| `google-calendar-view.js` / `.css` | Google連携の接続画面と週間表示への予定の描画 |

DOM監視は月表示側にまとめ、週間表示は月表示の更新通知を受ける。`classic.html` では、これらの追加機能を読み込まない。昼夜の配色とアナログ時計のデザインはクラシックと共通。

## テスト

配信するアプリにビルド工程やフレームワークは不要。開発用のテストはNode.js 22以上を使用する（検証環境は24）。依存はテスト用のPlaywrightだけ。

```sh
npm ci
npx playwright install chromium
npm test
```

`npm run test:unit` は日付の計算をNode標準テストで確認する。`npm run test:browser` は主要な操作をChromiumで確認し、確認用サーバーを自動起動・終了する。WebKitも確認する場合は、対応するシステムライブラリを用意して `npx playwright install webkit` と `npm run test:webkit` を実行する。既存のChromeを使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を指定できる。

自動テストの対象は、予報区の境界・島・週間区分、気象庁の発表時刻・日付境界・観測品質・欠測・提供元間の補完と障害時の切り替え、月・年・うるう日・タイムゾーンの境界、月移動と週の選択の競合、週間表示、日付と祝日、天気の失敗・キャッシュ・再取得、タイマーの復元・終了、スマホ縦横5サイズ、Google連携の予定分割・ページ分割・重複、別タブと別ブラウザーの分離、切断・期限切れ・アクセス拒否・通信失敗。外部APIは固定データに置き換え、実際のGoogle・Microsoft認証や端末の通知音・画面ロック中の動作は対象に含めない。WebKitでの確認は実機Safariの確認を代替しない。

Googleの予定・カレンダー一覧・選択状態・認証トークンは接続したタブのメモリだけに保持する。入力した公開情報のアプリID以外を端末ストレージや公開ファイルへ保存しない。Google側のアプリ登録と実際の接続は別途必要。Teams連携は別のPRで検討中。
